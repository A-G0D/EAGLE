# AGENTS.md - EAGLE

EAGLE (Experimental AI Global and Limited-area Ensemble forecast system) is
configuration and driver code for an end-to-end machine-learning weather
prediction pipeline. The pipeline is orchestrated by GNU Make and `uwtools`,
and the repository provisions its own conda environments. This is not the
Anemoi, ufs2arco, wxvx, or MET upstream code: bugs in those projects belong in
their own repositories.

Primary language: Python. Default branch: `main`. License: public domain
(CC0 1.0) for NOAA-authored code; see `LICENSE.md` for bundled dependencies.

## Repository layout

| Path | Contents |
|---|---|
| `Makefile` | Pipeline steps and developer tooling; run `make` to list targets. |
| `eagle/` | Python driver code. Each stage keeps `<stage>.py`, `<stage>.jsonschema`, and `<stage>_test.py` together. |
| `config/` | YAML fragments composed into a run configuration. |
| `envs/` | Conda environment definitions: `base`, `data`, `anemoi`, `visualization`, `wxvx`, `dev`. |
| `cuda/` | `cudascript` files (`none`, `dummy`, `ursa`) that make `nvcc` available during setup. |
| `setup`, `format` | Environment bootstrap and formatting scripts invoked by `make`. |
| `docs/` | Sphinx sources; build with `make -C docs`. |
| `notebooks/` | Example and analysis notebooks. |

`conda/` is generated by `make env` / `make devenv`, is gitignored, and must
never be edited or committed by hand.

## Toolchain

- GNU Make >= 3.82 (`docs/user_guide/quickstart.rst`).
- Conda (Miniforge, installed by `setup`) plus `uwtools` 2.21.* for drivers and
  config composition.
- Python pins live in `envs/*.yaml` (for example 3.12 in `envs/anemoi.yaml`,
  3.13 in `envs/visualization.yaml` and `envs/wxvx.yaml`).
- Developer tools from `envs/dev.yaml`: ruff 0.14, mypy 1.19, pytest 9 with
  `pytest-cov` and `pytest-randomly`, shellcheck 0.11, yamllint 1.38,
  shfmt 3.13, jq 1.8.

## Setup

Creating the environments downloads Miniforge, conda packages, and pip
packages; it needs roughly 50 GB of disk and can take a long time
(`docs/user_guide/quickstart.rst`). Do not re-run it when `conda/` already
exists.

```bash
# Runtime environments:
make env cudascript=<none|ursa|/path/to/cudascript>

# Runtime environments plus the developer tools above:
make devenv cudascript=<none|ursa|/path/to/cudascript>
```

`cudascript=none` is for systems where `nvcc` is already on `PATH`; see
`docs/user_guide/runtime_environment.rst` for the other options. The argument
is required.

## Build / test / lint (exact commands)

| Task | Command | Notes |
|---|---|---|
| List targets | `make` | Prints pipeline and tooling targets, then exits nonzero by design (`all` ends with `false`). |
| Format | `make format` | `./format eagle`: ruff format, shfmt, import sort, JSON key sort. |
| Lint | `make lint` | `ruff check` per module. |
| Type check | `make typecheck` | `mypy` per module. |
| Unit tests | `make unittest` | `pytest` per module. |
| Shell check | `make shellcheck` | `shellcheck` on `format` and `setup`. |
| YAML lint | `make yamllint` | `yamllint --no-warnings config/ envs/`. |
| All checks | `make test` | `lint`, `shellcheck`, `typecheck`, `yamllint`, `unittest`. |
| Docs build | `make -C docs` | Creates/updates a `docs` conda env; HTML in `docs/build/html/`. |

Without `mod`, the per-module targets loop over `eagle`, `data`, `inference`,
`training`, `visualization`, and `wxvx`. With `mod=<name>` they operate on one
module using that module's environment, for example `make lint mod=data`,
`make unittest mod=eagle`, or `make test mod=data`.

Before opening a PR, run `make format` and then `make test`, and paste the
commands and results into the PR body. `make format` rewrites files in place,
and CI fails if the tree is dirty after it (`.github/scripts/fmtcheck`).

## Configuration changes

Run configurations are composed from `config/*.yaml`, then validated against
the top-level JSON Schema:

```bash
make config compose=base:nested:ursa > eagle.yaml
make validate config=eagle.yaml
```

When adding or changing a configuration key, update the JSON Schema next to
the driver that consumes it (`eagle/<stage>/<stage>.jsonschema`, or
`eagle/eagle.jsonschema` for top-level keys) and the relevant page under
`docs/`.

## Expensive pipeline stages

Do not run `make data`, `make training`, `make inference`, `make vx-*`, or
`make vis-*` unless the developer explicitly asks. They download datasets,
submit Slurm jobs, train models, or generate forecasts, and the full quickstart
is currently supported only on Ursa (`docs/user_guide/quickstart.rst`). A
documentation or driver-logic change should be validated with the
code-quality targets above, not by running the pipeline.

Do not add the `eagle-ursa` label to a PR. The Ursa end-to-end workflow is
opt-in and is triggered by a maintainer after review.

## Code conventions

- Python style is enforced by `ruff` (`line-length = 88`, `select = ["ALL"]`
  with the project's ignores in `pyproject.toml`). Run `make format`; do not
  reformat unrelated code.
- Keep each driver's JSON Schema and tests beside its implementation in
  `eagle/`, following the existing `<stage>.py`, `<stage>.jsonschema`,
  `<stage>_test.py` pattern.
- Tests are pytest files named `*_test.py`. Module-specific runs use
  `--cov=eagle.<mod>`, and `pyproject.toml` sets `fail_under = 100`; new
  driver code needs tests that exercise it.
- Do not weaken, skip, or delete tests, schemas, or CI checks to make a change
  pass. If a test or schema is wrong, argue that separately.
- Keep changes scoped. New conda packages belong in `envs/<name>.yaml` and
  need justification in the PR.

## PR and commit rules

- Open or identify an issue first; the PR template requires a linked issue
  (`Resolves #N`).
- Branch from `main` and keep one concern per PR. Fill out the PR template,
  including the testing/verification section, and request review.
- PR descriptions become commit messages, so write a clear summary. Merge with
  "Squash and merge" unless preserving all commits is justified
  (`docs/community/contributing.rst`).
- Do not edit `.github/workflows/**`, `LICENSE.md`, or generated `conda/`
  unless that file is the subject of the change.
- AI-assisted changes: disclose the assistance in the PR description. The
  human submitter reviews the diff and is accountable for the change.

## Definition of done

- [ ] The change is linked to an issue and is the minimal diff for it.
- [ ] `make format` leaves no diff and `make test` passes, or the PR states
      exactly which targets could not run and why.
- [ ] New behavior has tests; JSON Schema and docs are updated when config or
      behavior changes.
- [ ] No secrets, tokens, account credentials, or machine-specific paths.
- [ ] AI-assistance disclosure is present.

## When something fails

1. Read the failing command's output and reproduce it before changing code.
2. For environment problems, check
   `docs/user_guide/runtime_environment.rst` and `docs/reference/faq.rst`, and
   state what could not run locally.
3. Do not mask failures with skips, retries, or relaxed checks.
